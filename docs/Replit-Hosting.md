# MacroSignals — GitHub and Replit setup

Prepared 12 September 2026. This source contains both the desktop application and the new mobile web edition. The web edition has not yet been deployed to your Replit account. The private source repository is [seymurtari/macrosignals](https://github.com/seymurtari/macrosignals). Start with **section 2** to import it into Replit.

## 1. GitHub repository (already created)

The private destination repository has been created. The steps below are retained only for setting up another copy; you do not need to repeat them.

1. Open [GitHub — new repository](https://github.com/new).
2. Select your `seymurtari` account and name it **macrosignals**.
3. Select **Private** and enable **Add a README file** so there is an initial branch.
4. Create it, then send its URL back in this conversation. I can upload the prepared project after the repository is accessible to the connection. If necessary, grant the GitHub connection access to this specific repository.

Do not enable GitHub Pages. GitHub will store the private source; Replit will run the server. Do not upload the Windows executable, personal CSVs, password, API keys or database connection string.

If you prefer to upload yourself: extract MacroSignals-Source.zip, open the repository, choose **Add file → Upload files**, and upload the files and folders inside the extracted project so `package.json` sits at the repository root. Include `.replit` and `.gitignore`; they may be hidden on your computer. Upload source files, not the ZIP itself. There are fewer than 100 files in the prepared source archive. The generated `dist` folders are optional because deployment rebuilds them.

[GitHub repository creation documentation](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository)

## 2. Import into Replit

Use your laptop browser for the initial setup.

1. Open [Replit Import](https://replit.com/import).
2. Choose **GitHub**, connect your GitHub account, and select the private `seymurtari/macrosignals` repository.
3. Complete the import. Keep the Replit project private and do not add collaborators.
4. Check that `package.json`, `.replit`, `web/`, `src/` and `core/` are at the project root.

You can also choose **ZIP** and import MacroSignals-Source.zip directly while GitHub upload is pending. Importing the ZIP does not put it on GitHub. This is an existing Node/React project; Replit Agent does not need to generate a replacement app.

[Replit import documentation](https://docs.replit.com/build/import-from-providers)

## 3. Configure storage and secrets

Open Replit's **Database** tool and ensure a PostgreSQL database is attached. The app creates its `macrosignals_data` table automatically; no manual schema entry is needed.

In **Secrets**, configure:

| Name | Value |
| --- | --- |
| `APP_PASSWORD` | A unique password generated by your password manager, preferably 32 random characters; the app requires at least 20 characters. This is the app password, separate from your Replit password. |
| `APP_ORIGIN` | The exact address you use to open this environment, including `https://`, without a path. Use the preview's external address for development and the published address for production. |
| `DATABASE_URL` | Replit's PostgreSQL connection string. Reuse the value supplied by its database integration; do not replace the production value with a development connection string. |
| `ELECTRON_SKIP_BINARY_DOWNLOAD` | `1` |
| `FRED_API_KEY` | Optional free 32-character FRED API key. Needed for first-release history; current revised history works without it. |

Keep these values in Secrets. Never put them in GitHub or paste them into this conversation. If your preview and deployment use separate environment settings, configure the correct `APP_ORIGIN` in each. The app rejects cross-origin changes intentionally.

Your phone and laptop share one owner workspace in the production database. Cached histories, imports, selections, watchlists, membership notes and rules are saved there. Opening another device loads the saved workspace; reload a page to pick up edits made on another device.

[Database credentials](https://docs.replit.com/features/data-and-storage/connection-details) · [Development and production databases](https://docs.replit.com/features/data-and-storage/development-and-production)

## 4. Run a preview

The project uses Node.js 22. In Replit's Shell, run:

```bash
ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci
npm run dev:web
```

The **Run** button uses `npm run dev:web` through `.replit`. Open the preview in a **new browser tab**, set `APP_ORIGIN` to that exact HTTPS origin, and restart the preview after changing a secret. Embedded previews are blocked by the app's framing protection.

Sign in with `APP_PASSWORD`. On **Trends & links**, click **Load free data**. Refresh retrieves indicators one at a time and saves each successful result. Errors preserve previously saved data. Cancel finishes the in-flight indicator, then stops.

Development can fall back to `.web-data` files when no database is configured. The published app deliberately refuses this fallback because hosted filesystem changes may not persist.

## 5. Publish the mobile application

1. Open **Publishing** and choose **Autoscale**. A Static deployment cannot run this application's login, database or FRED service.
2. Choose the published address. Set the production `APP_ORIGIN` to that exact HTTPS address before starting the server.
3. Enable or confirm the **production database**. Replit's current infrastructure provisions it when needed; legacy projects may show a **Create production database** switch. Confirm the deployment receives its production `DATABASE_URL`.
4. Use these settings, already included in `.replit`:

| Setting | Value |
| --- | --- |
| Build command | `ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci && npm run build:web` |
| Run command | `npm run start:web` |
| Port | `3000` (or the `PORT` provided by Replit) |
| Health path, if requested | `/healthz` |

5. For **Who can access your app**, select **Invite only** if available, in a personal workspace with no other members or invitees. Workspace administrators can access private deployments. Replit's account-specific availability has not been checked here.
6. The application also requires its own password on every deployment. If Starter does not offer private publishing, publishing a publicly reachable URL still presents only the login screen; the server protects dashboard assets and all data endpoints. Keep your source project private. Anyone who knows the app password can sign in, so do not share it.
7. Review the displayed cost and allowance, then publish. No subscription purchase is necessary merely to import this source. Stop if Replit requests an upgrade you do not want.
8. Open the published URL in a private/incognito browser window: you should see the MacroSignals login screen, or Replit's sign-in screen if its private-access option is enabled. After authenticating, confirm you can load a KPI and save a selection. Reload and open from your phone to confirm the same saved selection appears.

[Deployment types](https://docs.replit.com/features/publishing/deployment-types) · [Publishing access](https://docs.replit.com/features/publishing/private-deployments) · [Project configuration](https://docs.replit.com/features/project-setup/configuration)

## 6. Use it on your phone

Open the published HTTPS link in Safari or Chrome and enter the app password. The bottom navigation opens **Sources**, **KPI catalogue**, **Trends & links**, and **Analysis lab**. Use your browser's Add to Home Screen command for a shortcut. An internet connection is required; this is a responsive website, not an offline native app.

The catalogue has nine collapsible groups. Select KPIs there, then inspect their trends. Charts default to **20 years where available**; shorter histories remain shorter. The coverage list shows actual available dates for every selected KPI. The main chart can overlay up to five series.

Settings includes **Sign out**. Sessions expire after seven days. Rotating `APP_PASSWORD` and restarting/republishing invalidates old sessions. FRED credentials are managed through Replit Secrets; they are never returned to the browser or included in exports.

Daily refresh works only while an authenticated browser tab is open and visible. Autoscale can sleep when idle; this version does not pay for or schedule an always-running background task.

## 7. Move existing desktop preferences and data

1. In the Windows app, open **Settings & backup → Export settings**.
2. In the web app, use **Settings & backup → Restore settings** to load that JSON file.
3. Reload free histories with **Refresh data**.
4. For imported/paid histories, export each series as CSV from the desktop app and import it into the corresponding web KPI. If you assert first-release data, preserve the required availability dates.
5. Export research snapshots from the Analysis lab after running a test. Those exports freeze the tested inputs; full research JSON bundles are for inspection/reproduction and are not a bulk restore format.

The existing Windows cache is not automatically uploaded. Paid-source entitlements and permitted export rules continue to apply.

## Updating later

Update the source in GitHub, pull the new commit using Replit’s Git pane, and publish again with the same production database and secrets. Importing a GitHub repository is not a promise of automatic deployment on every commit. Do not recreate the database for routine code updates.

## Troubleshooting and verification limits

- **APP_PASSWORD error:** add a unique secret of at least 20 characters, then restart/republish.
- **APP_ORIGIN error / Request origin rejected:** use the exact HTTPS origin of the tab you opened, and the production address in deployment secrets. Do not include `/login` or another path.
- **DATABASE_URL required / Storage connection failed:** check the production database and its deployment connection string. The app intentionally will not publish using temporary local files.
- **Preview refuses to connect inside a frame:** open it in a new tab.
- **Electron downloads during install:** ensure `ELECTRON_SKIP_BINARY_DOWNLOAD=1` is set before `npm ci`.
- **No historical chart:** click Load free data or import the correct CSV; data-provider errors are shown without erasing earlier observations.
- **Saved preview data missing after publish:** development and production databases are separate. Restore your settings and reload/import data in the published app.
- **Link stops after a month:** check Starter's published-link expiry and current account options.

Automated verification covers the desktop regression suite, web sign-in/access and origin checks, browser bridge rendering, CSV import/export, saved-data restart recovery, worker-backed research, and concurrent PostgreSQL storage operations. PostgreSQL SQL was tested using an embedded PostgreSQL engine; a live Replit database connection and deployment were not available for testing. The interface uses responsive layouts, but physical iPhone/Android rendering and mobile file dialogs remain to be checked after deployment.
